当在 PyTorch 中写下一段模型代码时，我们通常不会关心它最后是怎样在 GPU 上执行的：
```python
y = torch.matmul(x, weight)
```
从程序员的角度来看，这只是一次矩阵乘法。但是真正执行时，系统还需要决定数据放在哪里、矩阵怎么分块、使用多少线程、是否适用 Tensor Core、数据以什么顺序访问，以及最终生成怎样的机器指令。
从 PyTorch 中的一行代码，到 GPU 上真正执行的 kernel，中间存在一个很长的软件栈。AI 编译器解决的就是其中非常重要的一部分问题：将我们描述的“模型要计算什么”，逐步转换成“硬件应该怎样计算”。
# 从传统编译器开始
传统编译器通常分为三个部分：前端、优化器和后端。编译过程以高级语言作为输入，前端主要是负责解析源代码的词法和语法分析，检查语法错误，并将源代码转化为中间表示。优化器则在前端的基础上，对中间代码进行优化，使得代码更加高效，后端负责将已经优化的中间代码转换成针对硬件平台的机器代码。
![[Pasted image 20260807212615.png]]
例如 C++程序经过 Clang 前端以后，会被转换成 LLVM IR，随后经过一系列优化 Pass，最后由 LLVM 后端生成 x86、ARM 等不同平台上的机器代码。其中 IR 是指中间表示，用于表示中间代码的数据结构，IR 既是连接前端和后端的桥梁，又是前端和后端解耦合的工具，优化器的转换和优化都是围绕 IR 实现的。早期如果没有统一的 IR，一种语言想支持一种新的硬件，就可能需要重新实现一套适配逻辑。
例如
```
x = 10 * 20
y = x + 0
```
编译器可以直接在编译阶段将其变成：
```
y = 200
```
常量折叠、死代码消除、循环展开等优化，本质上都是对 IR 进行分析和变换。该思想也直接影响了 AI 编译器，LLVM 中的 Pass 可以用流水线的视角展开：IR 依次经过不同 Pass，每个 Pass 只负责一种分析或变换，最终得到更适合执行的程序。
# 为什么不直接用传统编译器
![[Pasted image 20260807222851.png]]
表面来看，AI 编译器面对的问题和和 LLVM 很像，上面有不同框架，下面有不同硬件，似乎只需要通过传统编译器直接编译适配运行即可。但是真正的问题时，传统编译器理解的程序和神经网络程序并不处于一个抽象层级。主要从以下三个方面体现：
- 对领域特定计算抽象缺乏深度优化能力：传统编译器围绕标题、数组和指针等通用数据类型设计，其优化（如循环展开、向量化）主要优化这些结构。而 AI 计算的核心是张量（多维数组）和基于计算图的数据流。AI 编译器具备领域感知能力，能够实施传统编译器无法实现或效率低下的关键优化。
- 难以高效适配高度异构与可配置的 AI 加速器：AI 硬件生态高度多元化，从通用 GPU 到高度定制的 TPU、NPU，每种加速器都有其独特的计算单元、内存层次和指令集。传统编译器的后端通常针对 CPU 或标准 GPU 进行设计，其抽象层级较高。
- 无法区分并满足训练与推理场景的根本性差异需求：深度学习的工作流程主要分为训练和推理两大部分，其对编译器的需求有本质不同。

# AI 编译器
AI 编译器是一种针对 AI 和机器学习应用特别优化的编译器，它能够满足推理场景和训练场景不同需求，将高级语言编写的程序或训练好的模型文件转换成可以在特定硬件上高效执行的程序。主要以 Python 语言为前端，拥有多层 IR 设计，面向神经网络深度优化，针对不同芯片架构设计。
其目标主要有以下六点：
- 性能优化：极致降低训练，推理耗时，提升吞吐量。
- 资源利用：最大化硬件资源利用率，实现最优能效比。
- 模型压缩：压缩模型体积与计算量，适配移动端/嵌入式设备资源限制。
- 硬件兼容性：生成跨平台可执行代码，覆盖异构硬件架构。
- 梯度计算：自动生成高效反向传播代码，支持动态计算图微分。
- 并行计算：实施数据/模型/流水线并行策略，充分利用多设备算力。
![[ChatGPT Image Aug 7, 2026, 10_51_54 PM.png]]
AI 编译器与传统编译器仍然保留了相似的 Frontend → Optimizer → Backend 结构，只是不同阶段的处理对象发生了变化。AI 编译器的高层 IR 仍然保留张量、算子以及计算图的信息，因此很适合完成算子融合、常量折叠、公共子表达式消除和死代码消除等图级优化。随着编译过程继续向下进行，IR 会逐渐暴露循环、内存访问、线程映射和硬件指令等细节。

![[Pasted image 20260807224954.png]]
- 前端：计算图经过多种优化，如代数简化、操作融合、操作下沉、公共子表达式消除、死代码消除和静态内存规划等，得到初步优化的计算图；随后通过模式匹配和图重写等方法进一步优化，最终生成优化后的计算图。
- 后端：是 AI 编译器与硬件交互的关键部分，负责将优化后的中间表示转换为特定硬件平台（如 CPU、GPU 或 TPU）的高效代码，后端模块通常包括硬件特定的优化器，例如针对 GPU 的并行化策略，针对 TPU 的矩阵乘法优化，以及针对 FPGA 的流水线调度。此外，后端模块还可能集成自动调优技术，通过搜索算法找到最优的硬件参数配置，以最大化性能。

## 主流的 AI 编译器——TVM
TVM 是比较有代表性的 AI 编译器系统。其重要思想是将计算什么和怎样计算分隔开。假设现在要做的是一个矩阵乘法：
$$
C = A \times B
$$
数学定义已经确定了计算内容，但是怎样执行却有大量不同的选择：循环顺序如何安排？矩阵是否需要分块？每块多大？哪些循环放到 GPU block？哪些循环放到 thread？什么时候加载到共享内存？是否向量化？这些问题的选择最终得到的数学结果完全相同，但是性能可能会相差很多。

![[Pasted image 20260807230349.png]]
TVM 的经典工作流程大致如下：
- 从 TensorFlow、PyTorch 或 ONNX 等框架导入模型。
- 翻译成 TVM 的高级模型语言 Relay。
- 将 Relay 表示降级为 TE 表示。
- 使用 auto-tuning 模块 AutoTVM 或者 AutoScheduler 搜索最佳 Schedule。
- 为模型编译选择最佳配置。
- 降级为张量中间表示（TIR、TVM 的底层中间表示）。
- 编译成机器码。

同样一个算法，可以有很多 Schedule。与其完全依靠工程师手工寻找最佳实现，TVM 可以在调度空间中进行搜索。早期的 AutoTVM 更多是在人工编写好的模版中搜索参数，而 AutoScheduler 进一步减少了对人工调度模版的依赖。TVM 做的一件重要的事情就是将数学定义和硬件执行策略拆开，这对于支持不同硬件非常重要，因为计算本身通常不会改变，但是最优执行方式可能完全不同。

## 主流的 AI 编译器——MLIR
MLIR 是一种高度模块化的编译器基础设施，专门设计用于解决异构计算和领域特定编译的挑战。其核心思想是通过分层中间表示和可扩展的方言系统，统一不同抽象级别的计算表达，从而连接高级框架与底层硬件。这样做的好处是可以减少重复造轮子。一个新的编译器项目仍然可以拥有自己的 Dialect，但只需要实现从自己的 Dialect 到现有 Dialect 的转换，就能够继续复用后面的优化 Pass 和代码生成能力。

# 张量
深度神经网络的数据实际上是高度同质，高度结构化的，张量就是对这种非结构化数据的一种有效表示。张量是动态的高维数组在深度神经网络程序中的别名。张量实际上包含数据与描述这些数据的元信息。例如一个图像张量：
```python
shape = [3, 224, 224]
dtype = float32
```
其中的 `3 x 224 x 224` 不只是几个数组，其实际上告诉了程序通道、高度、宽度三个信息，同样的一串数字，因为 Shape 不同，就可以拥有完全不同的语义。
![[Pasted image 20260808094215.png]]

例如灰度图可以表示为 `[H,W]`，彩色图片可以表示为 `[C,H,W]`，加入 Batch 后可以用 `[N,C,H,W]` 来表示。大语言模型中的 KV Cache 甚至可以表示为五维张量：`[nblk, 2, nkvh, seq, dh]`，分别对应 Transformer Block、K/V Cache、 KV Head、序列长度以及单个 Head 的维度。

## 张量存储布局
张量的形状在许多计算中具有明确的语义，这些语义直接决定了计算的具体方式。例如在矩阵乘法中，一个 $M \times K$ 的矩阵与一个 $K \times N$ 的矩阵相乘，会得到一个 $M \times N$ 的矩阵，这里的输入和输出都是二阶张量，其阶数与形状共同定义了矩阵乘法的计算规则。
然而在基础的张量表示中，形状通常与其物理存储方式紧密绑定——类似 C 语言中的多维数组，采用连续的、密集的内存布局。这意味着如果我们希望改变张量的形状（例如进行转置或重塑），通常必须同时移动或复制其底层数据，由于张量常在简单结构下管理海量数据，直接进行此类操作将带来巨大的开销，例如对一个 $4096 \times 4096$ 的 FP16 矩阵做转置，需要移动至少约 32 MB 的数据，在串行访问模式下，这样的内存操作效率十分低下。
存储的布局引入了一个新的概念——“步长”，步长是一个与逻辑形状维度一一对应的数组，其定义了在某个逻辑维度上向前移动一个元素时，在物理内存中需要跳过的字节数（或元素个数）。例如，对于一个形状为 $(4,5)$ 且内存连续存储的二维张量，其默认步长通常是 $(5,1)$。这意味着在第 0 维（行）移动一行（即列数 5），内存地址需跳过 5 个元素，在第 1 维（列）移动一列，内存地址只需移动 1 个元素。

# AI 程序基本概念——计算图
此处的 AI 程序特指基于深度神经网络，操作大规模数据，并且几乎只跟数据产生交互的一种程序。AI 程序这样的特点使得开发者可以接受相比通用程序的开发者严格地多的限制，以换取开发的便利性。满足这样性质的 AI 程序由下述的三要素组成。
- 拓扑：基于深度神经网络，因此 AI 程序具有很强的时序性或层序性，即 AI 程序中在层级结构上一般只有顺序执行，控制流较少（循环展开），因此 AI 程序可以表示为有向无环图（DAG），称为拓扑（topology）。
- 张量：操作大规模数据，因此 AI 程序操作的基本数据类型不是单个变量，而是高维数组，在 AI 程序中，高维数组被称为张量。
- 算子：几乎只跟数据产生交互，尤其是不需要与 IO 外设交互，因此 AI 程序可以完全由数据计算的函数调用组成，不需要 IO 模块，在 AI 程序中，函数调用被称为算子。

AI 程序在表示上可以包含全三要素，典型方式是 ONNX，对于众所周知的模型结构也可以省略拓扑表示，常用于大语言模型，例如 safetensors 和 gguf。
开放神经网络交换（Open Neural Network Exchange， ONNX）是一套表示深度神经网络模型的开放格式，由微软和 Facebook 在 2017 年推出，ONNX 定义了一套与环境和平台无关的标准格式，为 AI 模型的互操作性提供了基础，使 AI 模型可以在不同框架和环境下交互使用。可使用免费的可视化工具 Netron 观察 ONNX 模型。
有了计算图以表示 AI 程序，就可以操作这三要素实现对 AI 程序的优化。操作图上信息的步骤称作图变换。AI 编译器中可能接触到的图变换操作包括以下三种 ：
- 张量推导：根据算子信息和输入张量信息推导输出张量信息。
- 图优化：通过改变计算图拓扑才能实现的模型优化，包括常量折叠，算子融合等。
- 核函数选择和优化：根据算子信息和输入输出张量信息，选择最优算子实现，不改变图拓扑。

# AI 程序基本概念——张量推导
张量推导对应的是一般编程时的类型推导。C++使用 `auto` 关键字定义自动推导类型的变量。作为编译器，类型推导功能是刚需，即使是前端不支持推导的语言比如 C 语言，在表达式嵌套时依然需要知道中间变量的类型才能完成编译。
AI 编译器中操作的基本单元是张量，所以对应张量推导，张量推导的逻辑是绑定在算子上的，一个算子就是一个函数，通过函数输入的类型确定输出的类型在通常情况下都是成立的。在 ONNX 算子定义中会写明推导的逻辑。ONNX 定义不支持步长机制，所以只推导输出张量的数据类型和形状。
